# Gloam 中文版 v1.13.0 发布说明

这是 Gloam 中文 fork 的**首版发布说明**。上游是 [halideworks/gloam](https://github.com/halideworks/gloam)，本仓库（[mentho7/gloam-cn](https://github.com/mentho7/gloam-cn)）从 tag `upstream-fork-point`（提交 `264b7e6`）分叉，此后累计 **35 个提交**。本文只讲这 35 个提交相对上游做了什么，以及你要不要在意。

写作口径按 [RELEASE.md](../../RELEASE.md) 的「Release notes」一节：面向"决定要不要在意这次更新"的读者，讲用户可见的变化与需要做的动作，不逐条罗列 diff。每条结论都标注对应提交的短 sha，可自行核对。

## 这次更新要不要在意

| 你关心的事 | 结论 |
| --- | --- |
| 界面能不能用中文 | **能，而且能中英随时切换**，不用重启；这是本次的主体工作 |
| 需要重装 / 重新校准吗 | **不需要**。本次没有改动校准数学与实测输出路径（判断依据见「注意：可能影响实测结果」） |
| 会丢配置吗 | 不会。另修了一个会把**未知的夜间模式档位显示成空白行**的缺陷 |
| 有没有安全修复 | 有：提权安装色彩仪驱动前现在强制校验固定哈希 |
| 稳定性 | 应用策略、报告不确定度、位置查找被抽成纯函数并有单测覆盖；布局问题改为由测量用例把关 |

## 一、多语言切换（i18n）

这一版把 Gloam 从"只有英文界面"变成**中英双语、运行期可切换**。界面文本不再散落在 XAML 与 C# 字符串里，而是收敛到 catalog（`src/Gloam/Resources/i18n/en-US.json`、`zh-Hans.json`），两套词条一一对齐。

### 1.1 默认语言与切换入口

- **仓库文档以简体中文为默认**：README 改为中文正文并保留英文版入口，同时加上中英切换徽章；非必要的上游文档被裁掉，避免中英两套说法的漂移（`dc26e4b`、`fc61fe5`）。
- **标题栏语言按钮**：位于主题切换左侧，点击即切换界面语言，显示的是**"点击后会切到的语言"**而不是当前语言（`913b51e`）。两字母代码而非语言全名，因为 32px 高的标题栏放不下「中文（简体中文）」。
- **切换是原地刷新**，不是"改设置后重启"：正在跑的校准、已打开的对话框、滚动位置都不丢（`c38c0b7`）。

> 界面初始语言如何解析（首次启动读设置还是跟随系统）属于本地化设计文档的范围，本文不逐行断言，详见 [docs/localization.md](../localization.md)。本文能实证的是：两套 catalog 完整对齐，任一语言下界面都不应出现另一种语言。

### 1.2 让"切了语言还有一半英文"不再复发

用户反馈的同一句投诉背后是三类不同成因，修法也不同（`c38c0b7`、`95bd59a`、`ce8331b`）：

| 成因 | 现象 | 修法 |
| --- | --- | --- |
| 纯 getter 属性 | VM 属性在被读取时才解析，切语言时没人发通知 | 切语言时以**空属性名**重发 `PropertyChanged`，让 WPF 整屏重解析一次 |
| 静态列表缓存 | 夜间模式选项把首次触达时的语言缓存住了，重发通知也没用 | 改为计算属性，不再持有静态列表 |
| 值住在字段里 | 字段存的是**已解析字符串**，重发通知只会重读同一个过期值 | 切语言时先重写字段、再发通知 |

`DashboardViewModel` 在 `Dispose` 里取消订阅 `CultureChanged` —— localizer 是进程单例，订阅活过窗口会让已关闭的 VM 一直被引用（`95bd59a`）。

### 1.3 覆盖面推进（按用户可见度排序，不按文件大小）

- **托盘菜单**完整中文化，含开机启动、游戏模式、tooltip，以及四个真会撞到的 toast（`4eee7fb`）。
- **设置窗口**翻译，并停止缓存已翻译的占位符（`ce8331b`）。
- **仪表盘**两屏收尾，文档截图改为从真实窗口生成而非拼图（`93628b7`）。
- **全界面端到端翻译**（`e76c8b9`）。
- **运行期拼接字符串**（状态机拼出的句子）不再漏英文（`e29753a`）。
- **预检面板**翻译，同时让审计能正确识别多行日志调用（`ed4fbcc`）。
- **校准报告**的标签、等级与建议本地化（`33aacd6`）。
- **审计看不见的短标签**补齐（`f65e676`）。

### 1.4 夜间模式文本策略与翻译刷新生命周期

这一版把夜间模式的文本解析从"三处各自降级"收敛成一套类型化策略，并抽出共享的刷新生命周期（`afec32f`、`22ef47d`）：

- **类型化文本策略**（`INightModeText`）：文本按类型解析，不再靠字符串拼接。
- **不缓存已翻译的选项**：夜间模式下拉的 `DefaultOptions` 不再把首次语言写死；切语言时绑定真刷新，而不是继续显示上一次的文本。
- **`LanguageRefreshSubscription`**：把"订阅语言变化 → 刷新 → 退订"收敛为一个可复用对象，避免每个窗口各写一遍并各忘一次退订。

同一处代码还修掉一个更隐蔽的问题：**未知（新版本写入或手工改坏的）夜间模式档位过去会被降级成空字符串**，界面上是三行空白、无异常也无日志。现在未知值有单一兜底词条、中英两套 catalog 都能解析，于是它至少是可见、可诊断的（`cab8287`）。

### 1.5 审计与回归测试

- 硬编码可见字符串审计此前把**不可能翻译**的东西算作"用户可见文本"：WPF 资源键（`ThemeAccent`）、颜色字面量（`#0E1116`）、自动化 id（`display-identify-close`）、数据文件名（`srgb_to_gamma2p2_sdr.icm`）。审计改为**只度量文本**后，指标才可信（`e76c8b9`）。
- 审计工具不再把自己的 catalog 键算进命中（`4eee7fb`）；短标签改用源感知阈值（`f65e676`）。
- UI 测试不再断言英文状态标签，改为断言行为（`CanStart == false`、重试命令可执行、重试确实被调用）（`e4f62b3`）—— 断言文案的测试在换语言时必然假失败。
- 类型化本地化与回归测试结论已写入文档（`488120a`）。

## 二、底层代码重构

这一版的重构目标不是"改结构好看"，而是把**过去只能靠肉眼与实机验证**的判断抽成可单测的纯函数，同时顺手补掉几处真实的安全与数据可靠性缺陷。

### 2.1 apply policy 隔离：优先级规则从"写在流程里"变成"可测的纯函数"

过去"这一次到底该输出多少开尔文、用不用游戏档"的判断散在 `GammaApplyService.ApplyAll` 的流程中间，与设置读取、定时器、硬件写入交织在一起，导致预览/游戏档/热键三者的优先级只能靠实机试（`4f4831c`）。

现在抽出 `GammaApplyPolicy.Resolve(input)`：

- 输入是一次请求边界上**一次性捕获**的策略输入（模式、是否手动校准、开尔文覆盖、夜间阻断、手动禁用、游戏档、锁定开尔文）。
- 解析器**不读设置、不读定时器、不碰硬件**，因此优先级可以逐条断言。
- 规则逐条保留：手动预览与开尔文覆盖优先于游戏档；`ForceDaylight` 归一为 6500K；`NightOps` 取 `min(基线, NightOpsKelvin)`；游戏档可覆盖 gamma 模式；**全局热键仍然是最终权威**，能从任何游戏档（含 Night Ops）恢复到中性输出。
- 另外给游戏会话的 profile 加了**防御性克隆**：应用过程中对 profile 的改动不会漏回已保存的会话。

### 2.2 报告计算抽离：不确定度预算不再依赖窗口

`ReportUncertaintyCalculator` 把"报告里的不确定度预算"从 `CalibrationReportWindow`（近 3000 行的窗口类）里搬出来，成为不依赖窗口与设置存储的静态计算（`4f4831c`）：

- 输入是测量结果集、目标、**已持久化的漂移比例**与仪器分类信息；计算失败时返回 null 并记一行日志，报告照常生成（不因为不确定度算不出来就整份报告失败）。
- 一段值得保留的注释被一起搬了出来：漂移项优先用本次运行**持久化**的 `PeakWhiteDriftFraction`，因为测量数据已被编排层做过漂移归一化，在这里重新分析等于恒零，会悄悄丢掉每一次补偿运行的漂移残差项；只有在持久化值缺失（例如从已保存 profile 重新打开的历史报告）时才回退到重新分析。

### 2.3 位置查找加固

地点检测（日出日落 / 位置相关能力）从窗口与网络调用混杂的实现里抽出 `LocationDetectionService`，并改走 HTTPS 端点、加了单测（`4f4831c`）。用户可感知的部分是：地点检测不再依赖明文 HTTP。

### 2.4 驱动安装：提权前强制校验固定哈希（安全修复）

`UsbDriverHelper` 会用 `Verb="runas"` 启动 `ArgyllCMS_install_USB.exe`，而该文件位于**当前用户可写**的目录（应用 argyll_cache、`%LOCALAPPDATA%\Argyll`、DisplayCAL 下载目录）。这样一来，预先放一个同名文件就构成**本地提权**：下载时虽做过哈希固定，但提权启动那一步什么都不再校验（`cab8287`）。

修复后：

- 提权前必须匹配**固定的 SHA-256**，否则不启动；
- 校验用的文件句柄以 `FileShare.Read` 持有，使"校验通过到启动"之间无法被换掉字节；
- 失败**fail-closed**，并作为独立结果回传给调用方，于是对话框能说"安装包未通过校验"，而不是给一个根本没跑起来的进程弹成功提示。

配套新增 `UsbDriverInstallerIntegrityTests`（`cab8287`）。

### 2.5 未知 profile 不再被清空

夜间模式档位的三个 `CatalogNightModeText` 分支各自把**无法识别的枚举值降级成 `string.Empty`**：界面上是三行空白，既不抛异常也不写日志，用户与支持人员都无从判断发生了什么（`cab8287`）。

现在改为**一张键表 + 单一兜底词条**，中英两套 catalog 都能解析。对用户的意义：持久化的档位如果是本版本还不认识的值（新版本写入、或被人手工改过），你会**看到它**，而不是看到一行空白。

### 2.6 显示输出请求与执行回执

`DispwinRunner.ApplyGamma` 过去返回 `void`，"跳过、被绕过、被取消、已是最新"这四种情况在调用方看来毫无区别（`41d4842`）。

现在返回 `OutputApplyStatus`（`Cancelled` / `Unchanged` / `Bypassed` 等），并新增 `DisplayOutputState` 与仪表盘上的执行回执：你能在界面上看到"这次输出请求到底发生了什么"，而不是只能猜。**注意：这是把既有结果显式化，判定分支与写入内容未变。**

### 2.7 工程结构

扁平 UI 工程拆成 Shell / Features / Infrastructure 三层（`54f781d`），这是后续所有界面与本地化改动能低成本推进的前提；它本身对用户不可见，但解释了为什么这一版能连续翻译整个界面而没造成大范围冲突。

## 三、排版与布局修复

### 3.1 用测量替代目测

过去的 UI 回归只能靠人打开窗口"看一眼像不像坏的"，于是排版问题要么靠用户报告，要么在换语言之后才暴露（`b431519`）。

这一版把布局判定变成了**可执行的测量**：

- 新增 `LayoutOverflowTests`：对控件测量实际尺寸，判定是否溢出容器，而不是截图比对。
- 新增 `UiFixtures` + `WpfTestHost`（扩充 100 行）：在测试进程里加载真实窗口与真实 catalog，使"测量"的对象就是用户看到的那个界面。
- 新增 `LanguageSwitchBehaviourTests`：把"切语言后文本必须真的变"变成断言，这是 1.2 三类缺陷的回归闸门。
- `UiSnapshotTests` 相应缩减（97 行变动、多数是删除），因为"整图比对"被更精确的测量取代。
- 文档截图生成（`DocumentationFigures`）纳入同一套宿主，图片来自真实窗口。

对用户的意义：这一版之后，"某个按钮在中文下被挤出边框"这类问题会在测试阶段被量出来，而不是留到你装上之后。

### 3.2 缩放图形重裁

文档里的放大示意图此前是从"已放大的整幅截图"里再截一次，边缘因此带上了相邻控件（`2706334`）。改为按原始坐标系计算裁剪矩形后重新裁切，图形边界干净且与说明文字对齐（`2706334`）。

这条改动本身只影响 `docs/` 下的图，不影响程序行为。

## 注意：可能影响实测结果

**结论：本次没有影响校准数学或实测输出的改动，不需要重跑校准。**

按 [RELEASE.md](../../RELEASE.md) 的发布检查清单，这一类改动指校准数学、LUT 生成、漂移处理、精修。逐项核对如下：

| 相关路径 | 本次是否改动 | 判断依据 |
| --- | --- | --- |
| 校准计算 / LUT 生成 | 未改公式 | 涉及 `GammaApplyService`、`DispwinRunner` 的提交只做两件事：把优先级判定抽成纯函数 `GammaApplyPolicy.Resolve`（规则逐条保留，`4f4831c`）、把 `void` 返回值改为状态枚举（判定分支未变，`41d4842`） |
| 漂移处理 | 未改算法 | `ReportUncertaintyCalculator` 是从窗口类**搬出**既有逻辑，含"优先用持久化漂移比例、缺失时才重新分析"的原注释一并保留，并新增单测（`4f4831c`） |
| 报告数值 | 未变 | 抽离的是计算**位置**而非计算**内容**；计算失败时仍回退为"不显示不确定度、报告照常生成" |
| 精修 / 硬件写入 | 未改 | 无提交触及写入路径；`DispwinRunner` 仅新增回执状态 |

因此本版的「色彩仪重校验」一项可以**明确跳过**，而不是留一个含义不清的空格。若你仍然想确认：本次唯一会改变你屏幕输出观感的可能是驱动安装流程（`cab8287`）——但那是在**安装**阶段，且失败会明确报错，不会静默改变已应用的校准。

## 升级后需要做什么

1. **什么都不用做。** 设置、校准 profile、报告都在 `%LocalAppData%\Gloam`，与安装目录分离，覆盖升级不受影响。
2. **想换语言**：点标题栏主题按钮左侧的语言按钮。切换即时生效，正在进行的校准不会被打断。
3. **如果之前见过界面上的空白行**（夜间模式档位区域）：升级后再看一眼，未识别的档位现在会显示为兜底文案而非空白。这属于你**升级后才会发现变好**的一类修复，不需要任何操作。
4. **如果色彩仪驱动需要安装**：安装前会先校验安装包哈希，校验不通过时会明确提示"未通过校验"并中止。此时请重新下载驱动，不要绕过。
