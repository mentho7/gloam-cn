## 二、v1.11.0（tag `v1.11.0-i18n.1` → `e4f62b31`）

> tag 注释原文：*Release candidate: en-US + zh-Hans live switching. 112 keys across tray, dashboard, settings. 1498 tests green, strict build clean.*

### 新增能力

- **运行期语言切换**，不是"改设置后重启"。托盘、仪表盘、设置窗口在切到简体中文时原地刷新文本，正在跑的校准、已打开的对话框、滚动位置都不丢。
- **标题栏语言按钮**：位于主题切换左侧，32px 高、自动宽、等宽字体、1px 边框。按钮显示的是**点击后会切换到的语言**（英文界面显示 `ZH`），而不是当前语言——显示当前语言会被读成状态指示器，用户还得猜它是不是按钮。用两字母代码而非原生语言名，因为「中文（简体中文）」放不进 32px 高的标题栏，且代码对任何未来 catalog 都适用、无需特例。
- **托盘菜单完整中文化**，含开机启动勾选、游戏模式标签、tooltip，以及用户真会撞到的四个 toast（夜间模式、游戏模式、光标下无显示器、游戏模式保存失败），新增 20 个 `tray.*` 键。

### 这一版踩到并修掉的三个缺陷（同一投诉的三种成因）

用户反馈是"切中文后半个界面还是英文"。三处根因互不相同，所以修法也不同，且都写进了 `docs/localization.md` 作为后续参考：

1. **纯 getter 属性**：本地化的 VM 属性在被读取时才解析，切文化时没人发 `PropertyChanged`，绑定就保持上一次解析出的文本。XAML 的 `{loc:Tr}` 会自动更新，于是同一屏里两种语言并存。修法是 `CultureChanged` 时以**空属性名**重发通知（`OnPropertyChanged(string.Empty)`，告知 WPF 全部属性都变了、一次重解析）。`DashboardViewModel` 与 `GamerModeItem` 都改了，且 `DashboardViewModel` 在 `Dispose` 里取消订阅——localizer 是进程单例，订阅活过窗口会让已关闭的 VM 一直被引用。
2. **静态列表缓存**：`NightModeAlgorithmOption.DefaultOptions` 原本是静态字段，首次触达时把当时语言的标签缓存住了；这种情况下**重发通知也没用**，因为 getter 返回的还是同一份缓存列表。改为计算属性。
3. **值住在字段里**：`"PLAYING NOW"` / `"Waiting for a saved game"` 这类字段存的是已解析字符串，"重发通知"只会重读同一个过期值。修法是切语言时**先重写字段、再发通知**。这两个是临时提示而非用户数据，重置成新语言比留一行旧语言更好。

### 验证

- 严格构建（`dotnet build src\Gloam.sln -c Release -p:GloamStrictBuild=true`）0 警告 0 错误。
- 1498 个测试通过（从 `m1-ui-structure` 的 1449 增长而来）。
- `--smoke` 冒烟模式报告 `catalogs [en-US, zh-Hans]`。

## 三、v1.12.0（tag `v1.12.0` → `e76c8b99`）

> tag 注释原文：*v1.12.0: Simplified Chinese is a usable primary language. 619 catalog keys, interface translated end to end, pseudo-locale layout pass, 1499 tests green.*

这是本地化工作的主峰：**57 个文件、832 个字符串迁移、catalog 从 112 键涨到 619 键**，中英双语完整。

### 迁移波次按"用户可见度"排，不按文件大小

仪表盘面板 → 游戏实验室窗口 → 对话框与基础设施 → 校准流程。理由是用户先看到的就是先要翻译的；按文件大小排会把最大的 `CalibrationReportWindow.xaml.cs`（2976 行）排在最前，而它恰恰最少被打开。

### 两个让大规模迁移不需要重写代码的机制

- **`Loc` 静态门面**：对已发布 localizer 的静态访问点。窗口、对话框、静态辅助各有十几个构造点，为了译一个按钮标题把 `ILocalizer` 穿过每一处是更差的交易。`Loc` 读的实例与 XAML 绑定读的是同一个，所以不存在两套文本源。
- **`ConfirmDialog.ConfirmKeys`**：确认对话框原先把**预解析好的字符串**当参数，于是每个调用点都成了自己的翻译点，且默认标签硬编码英文。改接**键** + 本地化默认值：调用方传键，对话框自己解析。

### 审计工具的重大修正（这一版的数字变化值得单独复核）

硬编码字符串扫描器此前把**根本不可能翻译**的东西算作"用户可见文本"：

- WPF 资源键 `ThemeAccent`
- 颜色字面量 `#0E1116`
- 自动化 id `display-identify-close`
- 数据文件名 `srgb_to_gamma2p2_sdr.icm`

后果是指标失真——`BrutalistTheme.cs` 被读成 52 个"可译字符串"，实际上那是一张颜色表；全局虚增约 120。排除后基线从 1540 掉到 708 是**指标变准**，不是因为一次提交就翻译了 800 条。同时补了回归测试防止这类模式再被计入。

另一个具体 bug：XAML 实体 `&amp;` 被当作字面文本存进了 catalog，导致翻译后的 `&` 会渲染成 `&amp;`，已逐条修正。

### 测试策略的必要转向

套件里所有 UI 测试改跑**真实的英文 catalog**（`TestLocalization.UseEnglish` 放在 module initializer 里）。原因：在 localizer 为 null 的情况下，迁移过的文本会解析成**键名**（`tray.openDashboard` 之类），断言句子的测试会因为与被测行为完全无关的原因失败。这也解释了为什么套件最后开始断言**键**而不是文案——两个断言英文状态文案的测试在 `e4f62b31` 已被删除（"Detection timed out" / "No colorimeter detected"），改成行为断言：`CanStart == false`、重试命令可执行、重试确实被调用。

### 伪本地化进场

中文截图**证明不了**排版扛得住翻译扩张——简体中文几乎总比英文窄。因此截图工具里加了伪语言（`qps-ploc`，+40% 文本长度、带重音、加括号），两个窗口在伪语言下均无截断。这是后面 `b4315198` 排版闸门的伏笔。

### 验证

1499 个测试通过；严格构建干净；`--smoke` 报告 `zh-Hans` 活跃且两个 catalog 均已加载。

## 四、v1.12.1（tag `v1.12.1` → `e29753ad`）

> tag 注释原文：*v1.12.1: runtime-composed strings localized (52), dump tooling, baseline 708 -> 657, 1500 tests green.*

v1.12.0 之后用户看到的残留缺陷是**"静态那半是中文、动态那半还是英文"**：

```
Added 12 games. Game Mode is paused…
Patch 24 of 40
Elapsed: 0:04 • Remaining: ~0:31
Activated: TL156MDMP31
```

原因是这些句子由字符串插值现场拼接，查表带不了运行期值，上一轮迁移时被整批跳过。**52 条**改走 `Loc.Format` 的命名占位符：

```csharp
// 之前
$"Added {count} games. Game Mode is paused…"
// 之后
Loc.Format("gamelab.added.games", ("count", count))
```

两个设计决定值得记下来：

- **占位符用语义名而非位置号**（`count` / `title` / `ceiling` / `screen`，不是 `p1` / `p2`）。只有这样译文才能改词序。实证：
  `"white {cct} K / {nits} nits, Duv {duv}"` → `"白色 {cct} K / {nits} 尼特, Duv {duv}"`，三个占位符在中文里换了位置，校验器仍能确认中文模板含全部名字。
- **格式说明符在调用点做，不进模板**。模板引擎故意只懂 `{name}`；加一套格式化迷你语言就得配套解析、转义和逐语言校验，而收益不如在数字所在处直接 `value.ToString("F0")`。

这一版还留下了两个工具，使下一轮不必从零开始：

- `tests/Gloam.Tests/LocalizationDumpTests.cs`：设 `GLOAM_DUMP_LOCALIZATION=<path>` 时导出每个剩余候选的 file / line / text；无环境变量时惰性不执行。基线 fixture 只存计数（适合棘轮，翻译过程中没用）。
- `_tools/i18n_migrate_interp.py`（仓外辅助）：把每个字面量拆成"模板 + 参数对"，使代码与两个 catalog 不会漂移；译文漏占位符时**拒绝写入**。

基线 708 → 657，catalog 619 → 669，1500 个测试通过。

## 五、v1.13.0（分支 `feat/v1.13.0` → `27063342`，**尚未打 tag**）

这一版的主题是**"把剩下的漏网文本抓出来，并让测试能测量排版"**，由四个提交 + 一个文档修正组成。

### 5.1 多行 log 调用审计（`ed4fbcc7`）

审计器原本按**单行**判断一个调用是不是 log：行里出现 `Log` 或方法名就跳过。真实调用常常换行，消息字面量落在一条既不含 `Log` 也不含方法名的续行上，于是面向开发者的文本被算作可译文本。改为**从调用起点追踪括号深度**——这让"跳过 log"不再依赖调用恰好被排版成几行。净减 13 个候选，它们从来不可译。

同轮另译 28 串：校准 preflight 面板 12 条（开跑前用户会读到的 SDR/HDR 不匹配、色度计校正、元数据警告）、托盘更新提示、profile-manager 与 report-history 状态行、夜间计划删除确认。catalog 669 → 696，基线 657 → 617（其中 361 属校准报告）。

### 5.2 校准报告本地化（`33aacd60`）

选定的取舍是**翻译面向人的文本，不动证据**：

- 指标名保留标识符——`ΔE2000`、`Duv`、`CCT`、`LUT` 不译；
- 数值保持数字；
- print / PDF builder 仍输出**相同列序**。

这样一位支持工程师拿到中英两种 UI 语言导出的报告，看到的是同样的数字在同样的位置。本轮 82 串：报告窗口 chrome 与分节标题、print/PDF builder 自己的标题（导出的文档与窗口保持一致）、六条等级句（excellent…poor）、九条后续建议。

**刻意不翻译**的：由碎片拼装的报告文本（如 `"… correction - use Verify above for the full after numbers."`）。这些碎片跨多个 `TextBlock` 折行，单独译每一片中文读起来会断裂——那需要先把段落合并，属于排版改动而不是字符串改动。

基线 617 → 490（报告部分 361 → 234，其余 256 不变），catalog 696 → 775。

### 5.3 审计看不见的短标签（`f65e6767`）

这个缺陷是**对渲染窗口做系统性人工复审**发现的，不是测试套件发现的：游戏实验室窗口里 `Apply`、`Add` 还是英文，周围全是中文。

根因在审计器，不在翻译：**短于 6 字符的单词一律不算可见文本**。于是 `Content="Apply"`（5 字符）、`Content="Add"`（3 字符）、"Exit"、"Type"、"Close" 对棘轮全部隐形。两轮迁移都报"无回归"，而用户最常点的按钮一直是英文。

阈值改为**源感知**：

- XAML 的 `Text` / `Content` / `Header` 属性按声明即文本，与长度无关；
- C# 字面量仍需下限，因为代码里的短字面量多是 `"Auto"` / `"Center"` / `"Wrap"` 这类 token。

这个区分是关键：全局降低阈值会多出 42 条、绝大多数是 C# token；源感知在完成本轮迁移后只多 2 条。

由此译出 `Close` / `Back` / `Type` / `Error` / `Exit` / `Apply`（新增 `common.*` 键），覆盖九个窗口——含崩溃对话框与校准向导；外加报告里的通道行（`Max`、`Error`、`Red`、`Green`、`Blue`、`White`）。

同一提交里还修了四处：

- `melanopic` 有三处被译成「**克**视素」（误读），与设置窗口的「黑视素」不一致，已全部统一；
- 游戏实验室的 7 个选项列表原本是**字段初始化器**，每个 `Label` 在构造时解析一次，切语言后组合框留在旧语言——改为计算属性；
- 替换 `ItemsSource` 刷新时，组合框会短暂没有匹配项，`TwoWay` 绑定把 `null` 写回 VM，**丢掉用户已经做出的选择**。这个回归是新增的语言切换测试抓到的，修法是刷新后重新断言每个值；
- `"N RESULTS"` 原是硬编码插值计数器，改为 catalog 复数条目；`GamerProfileEditorItem` 从不发 `PropertyChanged`，导致父级刷新后编辑器自己的控件仍留旧语言。

基线 490 → 492（指标变严，不是代码变差），1507 个测试通过。

### 5.4 排版闸门：测量而不是用眼睛看（`b4315198`）

三道新闸门，各覆盖套件此前**看不见**的一类失败：

**① `LayoutOverflowTests` —— 单行文本是否放得下。**

对仪表盘、游戏实验室、设置窗口里的每一个单行 `TextBlock`，按元素自身的字体设置测量排版，比较 "WPF 需要多宽" 与 "元素实际多宽"，不足即**用户读不到的文字**。在 `en-US` / `zh-Hans` / `qps-ploc` 三种语言下各跑一遍——伪语言才是关键，中文比英文短，中文截图证明不了排版扛得住翻译。它立刻抓到一处 265px 定宽列装载 catalog 句子在 +40% 时被省略号截断，已改为换行。

**② catalog 卫生 —— 译文是否真的翻译了。**

译文与源文**完全相同**的条目是静默的翻译失败。有 10 条按设计相同（品牌名、`Gamma 2.2`、单位符号），按 key 逐条列出并附原因，使得新增的"照抄源文"条目必须刻意加入白名单。

**③ `LanguageSwitchBehaviourTests` —— 切换后状态是否还在。**

打开真实的游戏实验室窗口、设置组合框选项、切语言、断言标签与选择都还在。它抓到的正是 5.3 里那个 `ItemsSource` 回归。

配套的测试基建：

- `WpfTestHost` 独占一条 STA 线程、一个 `Dispatcher` 和进程唯一允许创建的那个 `Application`，把所有 UI 测试 marshal 上去（两个测试类各自建 `Application` 时第二个会抛）；
- 替换进程级状态（localizer、`AppPaths`、`Application`）的测试共享一个**串行**集合，并行跑会让两者都 flaky；
- 固定等待改成 `PupUntil`（当等待是关于某个条件时，不要等固定时长）；
- `UiFixtures` 持有窗口构造器，使人工截图与排版闸门不会漂移。游戏实验室的 fixture 现带一份样例 profile——空编辑器面板会渲染出空白组合框，读起来像排版 bug。

结果：1507 个测试**连跑四次**全绿（此前每三次会 flake 一次）。

### 5.5 文档图修正（`27063342`）

高级面板的缩放图原来取自 viewport 截图，而那张截图在展开折叠区**之前**就保存了。fixture 开始带样例 profile 之后，面板移出裁剪区，图变成一条 1.7KB 的空白条——在交付归档里看起来像渲染失败。两处缩放图改为从 `-full` 截图取，裁剪覆盖字段行，使组合框取值（`Not detected` / `Automatic` / `Game window display(s)`）可读。

### 6.1 .NET 目标框架：一次往返，最终落在 .NET 10 LTS

这段在两小时内来回过一次，两次的理由都成立，值得完整记录：

**先升到 .NET 11**（`7efed3f6`）。触发原因是 **.NET 8 于 2026-11-10 停止支持**。8 个工程全部改为 `net11.0` / `net11.0-windows`。同时暴露出一个更根本的问题：

> `AnalysisLevel` 原本是 `latest-recommended`，规则集**随安装的 SDK 走**。换 SDK 就等于改变"构建是否通过"——这次升级冒出 **48 个新诊断**，而 `GloamStrictBuild` 把警告当错误处理，等于**没有人改动任何代码，构建就红了**。

因此改为**钉死** `11.0-recommended`，并把新冒出的 19 处诊断**修掉而不是抑制**：

| 诊断 | 数量 | 修法 |
| --- | --- | --- |
| `CA2263` | 15 | `Enum.IsDefined(typeof(T), v)` → `Enum.IsDefined(v)`；`Marshal.SizeOf(typeof(T))` → `SizeOf<T>()`；`GetDelegateForFunctionPointer` 用泛型重载；`Enum.GetValues(typeof(T)).Cast<T>()` → `GetValues<T>()` |
| `CS9191` | 2 | `Marshal.QueryInterface` 该接 `in Guid`，多余的 `ref` 已删 |
| `CA1872` | 1 | `BitConverter.ToString(hash).Replace("-", "")` → `Convert.ToHexString`（输出同为大写无分隔，已由既有的 profile-hash 持久化测试验证） |
| `WFO2000` | 1 | 测试里的 `TheoryData` 每次读属性都重建，改为缓存 |

`global.json` 地板在这一步设的是 **`11.0.100-rc.3`** 而不是 `11.0.100`——SemVer 把 RC 排在正式版**之下**，若要 `11.0.100` 而机器上只装了 RC，解析会直接失败。这正是第一次尝试失败的真正原因。验证：严格 Release 全新重建 0 警告 0 错误、**1494/1494** 测试、`publish` 292 个文件。

**再退回 .NET 10 LTS**（`79a2a9d9`）。理由是版本节奏而非技术限制：

> .NET 11 是 **STS**，下一次被迫升级会落到 .NET 13；.NET 10 是 **LTS**（支持到 2028-11-14），而 .NET 12 是下一个 LTS。**留在偶数版，就再也不用在截止日期压力下搬家。**

具体改动：8 个工程 `net11.0(-windows)` → `net10.0(-windows)`；`AnalysisLevel` 改回 `10.0-recommended`（**仍然钉死**，这个决定不回退）；`global.json` 地板 `10.0.100` + `allowPrerelease: false` + `rollForward: latestFeature`（装了 SDK 11 也会被**拒绝**，而不是静默使用）；CI 的 `dotnet-version` 改 `10.0.x`。`.NET 11` 期间的成果全部保留——**19 处诊断修复不回退**，`.gitattributes` 也不回退；整个 `.NET 11` 状态另存为 tag `net11-snapshot`（`6ea59adf`），需要时可整体回滚。按 SDK 10.0.403 验证：0 警告、1494/1494、`publish` 284 个文件、`--smoke` 正常。

### 6.2 行尾与二进制策略（`6ea59adf`）

仓库原先**没有** `.gitattributes`，行尾由各 clone 的 `core.autocrlf` 决定。本 checkout 的 `core.autocrlf=true` 与 `.editorconfig` 的 `end_of_line = lf` 直接冲突，导致每次提交都刷 `LF will be replaced by CRLF`。新增规则：

- `* text=auto eol=lf` —— 与 `.editorconfig` 一致；
- `.ps1` / `.cmd` / `.bat` 保持 CRLF —— `cmd.exe` 处理批处理里的裸 LF 会出错；
- 二进制资源（ICC 配置文件、字体、图片）声明为不可归一化。

重新归一化后**没有任何内容变更**（仓库内的 blob 本来就是 LF），这是一次纯规则变更。

### 6.3 UI 工程拆分（`54f781d0`，184 个文件）

原来 `src/Gloam/` 是**扁平目录**：四十来个窗口、对话框、主题辅助、线程工具和组合根混在一起。加一个功能要动五个不相关的文件夹，而且得猜哪个文件夹"拥有"那个窗口。

拆分前（`src/Gloam/` 根目录下平铺着窗口与对话框，`Services/` 与 `ViewModels/` 里混装跨功能的工具类）：

```

├── App.xaml(.cs)  Program.cs  MainWindow.xaml(.cs)
├── DashboardWindow.xaml(.cs)  SettingsWindow.xaml(.cs)
├── CalibrationWindow / CalibrationSetupWindow / CalibrationReportWindow / …
├── GameLabWindow.xaml(.cs)  NightModeScheduleControl.xaml(.cs)
├── ArgyllDownloadDialog / ConfirmDialog / CrashDialog / BusyDialog / …
├── Services/   BrutalistChrome、DarkTitleBar、ThemeDetector、HotkeyManager、
│               StartupManager、ToastService、UpdateService、ResourceExtractor、
│               SafeAsync、WindowTheme、WindowBoundsPersistence、Calibration*、
│               GameLibrary*、Hdr*、Measurement*、Probe*、Report*、Verification*…
└── ViewModels/ Action、AppExclusionItem、Calibration*、CrashDialog、Dashboard*、
                GamerModeItem、Monitor、NightModeSchedule、Settings、Toast、Tray
```

拆分后：

```
src/Gloam/
├── Shell/              App、Program、MainWindow —— 只有组合根
├── Features/
│   ├── Tray/  Dashboard/  Calibration/
│   └── GameLab/  NightMode/  Settings/
├── Infrastructure/     Dialogs、Theming、Platform
├── Controls/           跨功能共享控件
├── Themes/  Fonts/     留在根（绝对 pack URI 依赖它们）
├── Behaviors/  Resources/i18n/
```

目录迁移在 diff 里表现为 **82 个删除 + 对应数量的新增**——这是 `git` 在不开启重命名检测时的经典形态，不是真的删掉了 82 个功能。

配套的三处细节，都是为了"移动文件不会静默改变行为"：

1. **命名空间随目录**，并在 `Gloam.csproj` 里把各功能命名空间声明为 **project-level global usings**（`<Using Include="Gloam.Features.Calibration" />`）。用意是：一个功能就是一个模块，功能内部移动文件不该变成改几十处 `using`。
2. `BrutalistTheme` 从 `App.xaml.cs` 移到 `Infrastructure/Theming`——静态主题状态属于基础设施，组合根不该承载它。
3. **4 个窗口的 `ResourceDictionary` 相对 `Source` 改为绝对 pack URI**。它们相对窗口自身目录解析，窗口一移动主题就**静默失效**（不报错、只是样式丢了）。这一步已有一个测试抓到。

附带修了一个让测试工程**根本无法编译**的问题：`ReportHistoryWindowTests.cs` 里混入一个原始 `U+0085` 字节（UI 实际用的是 `U+2026` 省略号），已换成按钮真正渲染的省略号。验证：`dotnet build` 0 警告 0 错误、`dotnet test` **1449/1449**。

### 6.4 本地化引擎为什么用 JSON catalog 而不是 .resx（`c38c0b77`）

这一步的起点是零：应用完全没有本地化设施——没有 resx、不用 `ResourceManager`、不碰 `CultureInfo`，所有可见字符串都是 XAML 属性与 VM 代码里的英文字面量。

**为什么不用 .resx：**

- resx 每种语言都要**重新编译**；
- 加载期一次性解析；
- 切换语言等于**重建每个窗口**，丢掉在途状态：已打开的对话框、滚动位置、正在跑的校准。

catalog 走 indexer + `PropertyChanged("Item[]")`，可以**就地刷新文本**。额外的能力是：catalog 可以丢进 `%LOCALAPPDATA%\Gloam\i18n\` 覆盖或新增语言，**不用发版**——这才让社区翻译变得可行。

新增两个工程：`src/Gloam.Localization`（引擎，**不引用 WPF、不引用 Windows**）与 `src/Gloam.Localization.Wpf`（XAML 适配层：markup extension、binding source、字体策略）。引擎立项时目标框架是 `net8.0`（刻意压低，以证明它不依赖任何 Windows 或 WPF API）；随 6.1 的两次重定向，现在两者分别跟随主工程的 `net10.0` 与 `net10.0-windows`。

其余关键设计（`docs/localization.md` 有完整说明）：

- **`{name}` 命名占位符，不用 `{0}`**：词序各语言不同。位置占位符会逼译者改写语法去迁就英文实参顺序。校验器强制译文保留源文的占位符集合。
- **缺键返回键本身**并记录：坏绑定读起来是明显的 bug，而不是一片空白。
- **回退链** `zh-CN → zh-Hans → zh → en-US`，再退到任何共享该语言的 catalog。
- **复数按 CLDR 类别**：中文一种、英文两种。把复数条目**扁平化成字符串是校验错误**，不是静默丢数。
- **CJK 字体替换**：CJK 文化下 `BodyFont` / `DisplayFont` token 换成支持 CJK 的字族。内嵌字体仅含拉丁字形，靠 WPF 逐字形回退避免豆腐块，但会产生混杂的度量和字重。
- **内嵌 catalog 是基线**，外部目录逐键叠加、**后者胜**；畸形外部文件跳过并上报，**绝不致命**——它是启动路径上的用户输入。

治理（`tests/Gloam.Tests/LocalizationAuditTests.cs`）：断言每个 XAML 键存在于源 catalog、没有未被引用的键、每个文件的硬编码可见字符串数不超过已提交基线。新增 UI 文本跑到 catalog 外就红。

接线：`SettingsManager` 增加持久化的 `Language`（`null` = 跟随 Windows）；`App` 发布 `LocalizedStrings.Default` 并在**首个窗口解析前**应用启动文化；`--smoke` 也解析 localizer，坏 catalog 会挂冒烟而不是发出去。

顺手修的一个启动崩溃：`CultureChain.TryParse` 只捕获 `CultureNotFoundException`，但畸形 tag（含非法字符）抛的是基类 `ArgumentException`——手改 `%LOCALAPPDATA%\Gloam\settings.json` 里的语言字段会崩启动，而这正是该方法存在的理由。

### 7.1 apply 策略抽取（`4f4831ca`）

### 7.3 显示输出请求与执行回执（`41d4842d`）

```csharp
public enum OutputApplyStatus   { Pending, Applied, Unchanged, Bypassed, Cancelled, Failed }
```

到这一步，"切语言后某处仍显示旧语言"已经被修过三种变体，每次都是逐个 VM 打补丁。这两个提交把它抽象掉：
